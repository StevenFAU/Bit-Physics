### Self-caught correction (COMMIT 5; acceptance-gate verification)

The acceptance gate caught a latent bug in the I6 lock
(`tools/testkit/lfs_migration/test_i6_convention_12.py`): `_backfill_commits()` matched
back-fill commits with `git log --grep=back-fill`, which searches the **whole** message and so
falsely caught commits 1/3 once they were in range (their bodies *describe* this lock). COMMIT 5
re-scopes the match to the **subject line** (a back-fill commit is identified by its subject, not a
prose mention). The fix changes test logic only — the test's outcome, node id, and PASSED output are
unchanged, so the COMMIT-1 failing-tests-output-hash `9644a435…` **still reproduces byte-identically**
at HEAD. COMMIT 5 touches the test file + this ledger note; its subject deliberately avoids
"back-fill" so the corrected lock does not classify the fix itself as a back-fill commit. SHA recorded
in the coordinator summary (terminal correction; not committed-then-back-filled).
