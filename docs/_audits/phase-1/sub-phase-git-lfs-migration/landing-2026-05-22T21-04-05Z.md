**Scope decision:** Adopt Git LFS for the `captures/` directory.
Migrate all existing `captures/**/*.h5` files into LFS storage.

## 2. Migration record

### 2.1 Procedure executed

(FACT — `git-lfs/3.4.1 (GitHub; linux amd64; go 1.22.2)` installed
locally per `which git-lfs` → `/usr/bin/git-lfs`.)

```
S1. git lfs install                                        # repo hooks added
S1. git tag pre-lfs-migration-backup 64ef8f1               # recovery anchor
S1. git stash push -u -m "pre-lfs-migration-stash"         # working tree clean
S3. git lfs migrate import \
      --include="captures/**/*.h5" \
      --object-map=/tmp/lfs-migration/sha-map.csv \
      --verbose \
      main ^d0c7eb7
S3. git lfs checkout                                       # smudge pointers → binaries
S3. git stash pop
S5. git push origin main                                   # fast-forward (NOT force)
```

### 2.2 Migration scope — narrower than operator anticipated

The prompted scope was "from `fa36ca9` forward into LFS storage". The
actual `git lfs migrate import` behavior is more conservative: its
default filter is "only files added in commits which do not exist on
any remote." Even though `main ^d0c7eb7` was supplied as an explicit
rev-range, git-lfs migrate honored its "un-pushed only" filter and
rewrote ONLY the 11 commits between `origin/main` (`34c7d34`) and the
pre-migration HEAD (`64ef8f1`) — the entire **eulerian-smoke sub-phase
chain**.

(FACT — sub-phase-particle-fluids-sph-water Stage 1
(`fa36ca9`) + Stage 2 (`281c74f` → `17850e2`),
sub-phase-mutation-script-hotfix (`614253f` → `27304d0`), and
sub-phase-conventions-consolidation (`7a7c07a` → `34c7d34`)
were ALREADY on `origin/main` at the moment of migration. Their
commits were NOT rewritten.)

This has two beneficial consequences:

1. **Audit-chain SHA references for pre-eulerian-smoke audits remain
   valid.** The `head_sha:` fields in the sph-water, mutation-script-hotfix,
   and conventions-consolidation landing audits still resolve correctly
   post-migration.

2. **The push is a FAST-FORWARD, not a force-push.** `origin/main`
   (`34c7d34`) is the direct parent of the first rewritten commit
   (`164b60f`). No history is rewound on the remote. The
   `--force-with-lease` posture pre-emptively framed in the prompt was
   not needed.
