# Replay-tool hotfix — repair complete

## 1. Defect summary

(FACT — parent audit `docs/_audits/phase-1/sub-phase-continuous-ca-rd3d/stage-0-blocked-replay-2026-05-20T18-52-10Z.md`.)

`tools/integrity/integrity/scripts/replay_prior_phase.py`'s `GATE_COMMANDS` carried argvs whose first token was `sys.executable`, then ran them under `cwd=worktree` via `subprocess.run`. `sys.executable` is the OUTER repository's interpreter and the outer `.venv` editable-installs the workspace's `integrity` package, so `python -m integrity` (and `python -m integrity.scripts.gate_helpers …`) under that interpreter imported the OUTER repository's integrity source — i.e. HEAD's tool — against the worktree's tagged content. The replay therefore mixed HEAD-tool with tag-content (a category error: the replay's job is to verify what the tagged commit attested to USING the tagged commit's own gate logic). The specific divergence that surfaced this defect was HEAD's `tools/integrity/integrity/cat3_numerical/golden_values.py::_SUBDIRS_PICKED_UP` recursing into `agent-based/` (extended at agent-based Stage 2 commit `d156792`), where the v0.1.0-phase-1 tables are still 1-anchor (the lift to 3 anchors landed post-tag at `3ce7809`).

## 2. Repair shape

**Shape (a-2) taken — worktree's own `.venv/bin/python`** (per the parent audit § 4 default lean). Rationale + S2 investigation result:

- S1 re-anchor on `_checkout_worktree` confirmed the existing `uv sync --frozen --all-packages --all-extras` invocation (landed at Phase 1 commit `131f996`) — this materializes `.venv/bin/python` in the worktree.
- S2 manual probe: `git worktree add --detach /tmp/bp-probe-v010 v0.1.0-phase-1` → `uv sync …` → `.venv/bin/python -m integrity --help` resolved correctly. `.venv/bin/python -m integrity --all --mode strict` exited 0 with the inherited 12 SOFT_WARN and **0 HARD_FAIL** at v0.1.0-phase-1 — the post-S1 (substitution-applied) end-state.
- The substitution was implemented as a single helper `_resolve_cmd_for_worktree(cmd, worktree)` that rewrites every `sys.executable` token in the argv to `worktree/.venv/bin/python`. Stub fixtures lacking a `.venv` fall through to the original argv unchanged — preserves the existing unit-test path. `uv`-based argvs are untouched (correct as-is; `cwd=worktree` directs `uv` to the worktree's `.venv`).

Shape (a-1) (PYTHONPATH manipulation with the outer interpreter) was not needed; (a-2) had zero implementation friction.

### 6.1 What the tests assert

Five new tests added additively to the existing `test_replay_prior_phase.py`:

1. **`test_resolve_cmd_for_worktree_substitutes_sys_executable_with_venv_python`** — load-bearing unit test on the helper. 2. **`test_resolve_cmd_for_worktree_substitution_directs_subprocess_to_stub`** — end-to-end via `subprocess.run`. Confirms the substitution actually directs subprocess to a different binary (stub marker observable in stdout; outer interpreter, run with the same argv, does NOT emit the marker — the by-contrast check guards against stub-vs-outer wiring inversions).
3. **`test_resolve_cmd_for_worktree_passes_through_when_no_venv`** — stub-fixture compatibility. Worktree without a `.venv` returns the original argv unchanged. Preserves the existing unit-test path.
4. **`test_resolve_cmd_for_worktree_leaves_uv_argv_untouched`** — narrow-scope guard. `uv run …` argvs are returned unchanged (no `sys.executable` token to substitute).
5. **`test_replay_uses_worktree_integrity_not_head`** — integration via `replay()`. Synthetic version-skew (tag-snapshot `check.py` exits 0; HEAD-snapshot exits 1); confirms `replay("v0-stub-phase", …)` exercises the tag-snapshot through `cwd=worktree`'s filesystem-resolution.
