## §2 — Common batch posture (the differentiable-sim architecture)

Every core sim follows the SAME verification architecture, built on the WU-A substrate
confirmed present at HEAD (§9). This is the inheritance backbone; §3 records per-sim
deltas only.

### 2.1 Two verification surfaces per sim

1. **Forward-equivalence (WU-F differentiable axis — NOT a new golden table).** The diff
   variant re-implements the forward map in a tape-differentiable form
   (`InverseProblem.forward`, `ti.field(..., needs_grad=True)` / `wp.array(..., requires_grad=True)`).
   Its forward output must equal the **landed reference sibling's** forward within
   `equivalence.variant` axis `differentiable` (`relative_max 1e-2`, default `1e-3`).
   Anchored to the reference (which itself carries ≥3 forward anchors). **Anti-pattern
   guard:** never widen past the WU-F cap to force a pass (§S/§F.3).

2. **Gradient golden table (NEW; gate-4; ≥3 INDEPENDENT anchors).** The autodiff gradient
   `∂Loss/∂params` at canonical points. The three independent anchors are **(A1)** an
   analytic gradient on a reduced/limiting case (closed-form), **(A2)** the central
   finite-difference baseline (`common_*.autodiff.finite_difference_gradient`, central,
   O(ε²), ε=1e-4 — the numerical-baseline exemption per close-R2), and **(A3)** a
   *second, source-distinct* reference (a published differentiable-method result, or a
   second analytic derivation on a different physical term). Per-sim A1/A2/A3 are named in
   §4.

3. **Inverse-problem recovery (integration test, not a golden table).** A planted-parameter
   recovery: optimize (`adam`/`lbfgs` via `make_optimizer`) to recover a known parameter
   from a synthetic target; assert convergence within tol. Uses the WU-A
   `ParameterIDProblem` / `InitialStateRecoveryProblem` / `ControlProblem` templates.

### 2.2 Determinism (cleaner than learned-dynamics)

Unlike NN training, these are **full-batch deterministic** inverse problems (no stochastic
minibatching). Posture (MEASURE-then-declare at Stage 1b, do not assume):
- **forward**: inherit the reference sibling's measured posture (RD-2D-D / lenia /
  mpm-D / eulerian-smoke-E all carry registry rows) — expected `bit-exact`,
  `same-stack-same-hw`.
- **gradient**: the adjoint/tape gradient is a deterministic function of fixed inputs →
  expected `bit-exact`, `same-stack-same-hw`. MEASURE via `run_twice_and_diff` /
  `assert_deterministic_run`; **re-declare on evidence** (no EFECT needed — there is no
  training-loss distribution here; this is the key relief vs pinn-poisson/learned-dynamics).
- Registry rows: probe the registry shape at Stage 0 (§S.2); likely two rows
  `<category>.<sim>.diff.{forward,gradient}` OR a single diff row — follow the landed
  registry convention, do not invent.

### 2.3 Capture exercises `gradient_fields` (schema 1.1.0)

The canonical capture is the inverse-problem solution: the recovered field + the
optimization trajectory, with the **`gradient_fields` capture key populated** (the WU-A
schema-1.1.0 addition — this batch is the first real consumer of `gradient_fields`).
Built via `common_warp.capture.write_frames_capture` (Stack E) or the common-py
`Writer` + `Manifest` (Stack D). Determinism declaration (§2.2) ↔ capture sidecar `claimed`.

### 2.4 Per-sim mutation target (4.1 carry-forward, §8.7)

Each sim ships an `invariants.py` (PBT source) and possibly an MMS/analytic-solution
source → register a per-sim mutmut target for that source (the 4.1 narrowing excluded
`sims/*/invariants.py` and per-sim MMS from the shared targets, so each new sim must
re-establish its own). MEASURE; **advisory** unless it clears its floor on
**oracle-grounded** tests (snapshots forbidden — same rule as 4.1).

### 4.1 — reaction-diffusion-2d-diff

**Golden table G1 — `∂Loss/∂D` (diffusion-coefficient gradient), canonical points.**
- **A1 (analytic, forward-physics gradient):** single-Fourier-mode decay of the linear
  diffusion operator: `û_k(t) = û_k(0)·exp(−D k² t)` ⇒ `∂û_k/∂D = −k² t·û_k(0)·exp(−D k² t)`,
  closed-form. SOURCE: heat-equation spectral solution — **standard PDE text** (e.g. Evans,
  *PDE* 2e, Ch. 2 "Heat Equation"; or Strauss, *PDE* 2e, Ch. 4). *Stage-0: verify the exact
  section; cite the separation-of-variables / Fourier solution, not a wrong sub-section.*
- **A2 (numerical baseline):** central FD via `common_py.autodiff.finite_difference_gradient`
  (ε=1e-4, O(ε²)). SOURCE: independent numerical method (close-R2 numerical-baseline exemption).
- **A3 (independent — landed MMS):** the in-repo `mms/solutions/reaction_diffusion_2d/`
  manufactured solution. The forward residual is anchored to the manufactured forcing; the
  parameter-sensitivity is cross-checked against the manufactured solution's analytic
  derivative. SOURCE: the landed MMS derivation (`derivation.md`) — distinct from A1/A2.
- **MMS strategy:** RD-2D is the MMS-bearing member. Manufactured `u*(x,y,t)` with computed
  forcing; **expected spatial convergence O(h²)** (2nd-order central Laplacian — same order
  the reference's `test_code_verification.py` already establishes). The diff variant's
  forward reproduces this via the §2.1 forward-equivalence check.
- **Forward-equivalence:** diff.forward == `reaction-diffusion-2d-stack-d` within
  WU-F `differentiable` (rel ≤ 1e-3).

### 4.2 — lenia-diff

**Golden table G1 — `∂Loss/∂μ`, `∂Loss/∂σ` (growth-parameter gradient), single-cell + small-grid.**
- **A1 (analytic, growth-function gradient):** Lenia update
  `u' = clip(u + dt·G(U∗K))`, Gaussian growth `G(x)=2·exp(−(x−μ)²/2σ²)−1`. `∂G/∂μ`, `∂G/∂σ`
  closed-form; for a single convolution value `∂u'/∂μ` is hand-derivable. SOURCE: **Chan,
  B.W.-C. (2019), "Lenia: Biology of Artificial Life," Complex Systems 28(3)** (arXiv:1812.05433)
  — growth/kernel definitions. *Stage-0: verify the growth-function form against the paper.*
- **A2 (numerical baseline):** central FD via `finite_difference_gradient`.
- **A3 (independent — second analytic / published):** the **convolution-kernel gradient**
  path (`∂K/∂(kernel params)`), a hand-derivation distinct from A1's growth path; OR the
  published differentiable-Lenia formulation — **Flow-Lenia (Plantec et al., 2023, ALIFE)**.
  *Stage-0: web-re-verify the Flow-Lenia reference + that it differentiates the
  growth/kernel composition; if it does not cleanly anchor, fall back to the second analytic
  kernel-gradient derivation (which suffices for the ≥3-distinct-source rule).*
- **MMS:** N/A (Lenia is not a smooth-PDE MMS target). Verification rests on the
  analytic kernel/growth goldens + the gradient golden.
- **Forward-equivalence:** diff.forward == `lenia` within WU-F `differentiable`, **scoped to
  the smooth interior** (§3.2 D-SMOOTH).

### 4.3 — mpm-multimaterial-diff

- **A1 (analytic, ballistic limit):** single particle under gravity with no grid coupling:

  differentiable-MPM elastic example whose gradients are finite-difference-validated in the
  paper. SOURCE: published paper. *Stage-0: web-re-verify the exact example + the FD-check

- **Forward-equivalence:** diff.forward == `mpm-multimaterial-stack-d` within WU-F `differentiable`.

### 4.4 — eulerian-smoke-diff
