## §1 — CUDA-fallback disposition (BLOCKED runtime; CPU surface lands)

Newton's solver runtime (`NewtonBackend.step`/`.state`/`.newton_instance`)
requires the `newton` package **and** CUDA 12 (driver 545+). Both are absent.
Per the dispatch ("surface BLOCKED, do NOT silently CPU-fallback") + the
operator-pre-ratified CPU-fallback (plan §7.5 v9 addendum: "CPU determinism + USD
export validates"; spec §12.8), WU-D lands the **CPU-deliverable surface** and
surfaces the runtime **BLOCKED loudly**:

| Surface | Disposition | CPU-runnable? |
|---|---|---|
| `NewtonBackend` metadata (SOLVERS ×6, solver validation, `determinism_declaration`) | LANDED | yes |
| `NewtonBackend` runtime (`step`/`state`/`newton_instance`/`reset_to_initial`) | **BLOCKED** — lazy-imports `newton` + CUDA-gates; raises a clear `RuntimeError` (never a silent no-op) | no (CUDA) |
| `NewtonState` / `DeterminismDeclaration` dataclasses | LANDED | yes |
| `common_warp.usd.create_scene_template` + `export_capture_to_usd` | LANDED (USD is CPU-only; `usd-core` installed) | yes |
| PBT `usd_round_trip_preserves_pose` + `determinism_declaration_consistent` | LANDED | yes |
| PBT `solver_no_overpenetration` (suggested) | **BLOCKED** (needs the Newton solver runtime = CUDA) | no |

This satisfies the ratified "CPU determinism + USD export validates" acceptance;
the GPU solver runtime is the Phase-4.5 sim-runtime concern (mirrors WU-B's
`SparseVolume.from_voxels` CUDA-gating).
