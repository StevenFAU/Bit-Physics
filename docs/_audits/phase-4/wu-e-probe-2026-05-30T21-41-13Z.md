## §1 — §0.3 SHIFTs taken

1. **common_py.learned is NOT eagerly registered in `common_py/__init__`.** The
   plan C2 says "register learned submodule", but `common_py.learned` eagerly
   imports `torch` + `lightning` (neither is a common-py base dep — common-py's
   base stack is Taichi). Eager registration would force those heavy deps on
   **every** common-py consumer (all Phase-1/2/3 Stack-D sims). It is importable
   on demand as `common_py.learned`. **common_warp.learned IS registered**
   (`from . import autodiff, learned, newton, sparse, usd`) — it is import-light
   (bridges import only `warp`; the PhysicsNeMo adapter lazy-imports physicsnemo).
2. **Module path** — flat src-layout (`common/common-py/src/common_py/learned/`,
   `common/common-warp/src/common_warp/learned/`) per the WU-A precedent, not the
   plan's `common/common-py/learned/`.
3. **No `TrainingLoop` class** (per plan v6 — Lightning adopted directly).
   `default_trainer()` returns a configured `lightning.pytorch.Trainer`.
