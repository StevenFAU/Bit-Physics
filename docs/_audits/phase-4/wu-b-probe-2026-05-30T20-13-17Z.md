## §2 — The Warp-volume CPU/CUDA constraint (FACT — measured, load-bearing)

Warp 1.13.0 grid **allocation** (`wp.Volume.allocate_by_voxels`,
`load_from_numpy`) raises `"Only CUDA devices are supported for
allocate_by_tiles"` on CPU. The grid **load** path (`wp.Volume.load_from_nvdb`)
works on CPU (it `np.frombuffer`s a pre-built NanoVDB buffer — no
`allocate_by_tiles`). Consequences:

- The Phase-4.0 WU-B surface is fully CPU-deliverable: the host-only C++
  `bit_physics::nanovdb` writer builds the sparse grid + writes `.nvdb`
  (NanoVDB `build::Grid` → `createNanoGrid` → `writeGrid`, header-only, g++),
  and Python `common_warp.sparse.SparseVolume.from_nvdb` loads + samples it on
  CPU (`wp.volume_lookup_f` in a kernel — verified, values exact, inactive →
  background).
- **`SparseVolume.from_voxels` (runtime allocation) requires CUDA** and raises
  `NotImplementedError` on CPU with a clear message. This is the **Phase-4.2
  sparse-sim runtime constraint** (mirrors WU-D's Newton CUDA dependency):
  sparse-variant sims that allocate volumes at runtime need a CUDA device.
  Surfaced here, not forced. (Not a WU-B blocker — WU-B ships the
  infrastructure; the constraint binds Phase-4.2 sim runtime.)
- A loaded `wp.Volume`'s `get_voxel_count()` returns **leaf-allocated** voxels
  (a full 8³ block per touched leaf), NOT the active count (the project's
  4-voxel fixture reports 512). The active topology is a **capture-manifest**
  concept (`active_mask`, recorded at write time), never inferred from the
  loaded volume. The Python `SparseVolume.allocated_voxel_count` is named to
  reflect this; the active mask lives in `ActiveMask`.

## §4 — PBT placement (FACT)

The two declared sparse-volume invariants (active-mask membership preserved
through write→read; inactive reads return the sparse default) are exercised as
a **40-trial randomized property test in the C++ ctest** (`test_io.cpp`), where
the write happens (Warp allocation is CUDA-only, so the host C++ writer owns the
write side on CPU — mirroring the mass-spring-cloth "PBT where the sim runs"
precedent). Python-side PBT covers the `ActiveMask` invariants (count = mask sum;
topology hash depends only on the active set + is collision-sensitive).
