## §1 — §0.3 SHIFTs taken (landed reality wins over stale plan prose)

1. **Package code path.** Plan § 7.2 C1 lists `common/common-py/autodiff/…`
   (flat). Landed reality is `src/`-layout: code under
   `common/common-py/src/common_py/autodiff/` and
   `common/common-warp/src/common_warp/autodiff/`; tests under each package's
   existing `tests/` home. Followed landed reality.

2. **common-py has no `write_capture` function** (pre-dispatch probe §4). The
   schema-version surface is the `Manifest` dataclass `schema_version` field +
   the new module constant `MAX_SUPPORTED_VERSION`. NO function kwarg added in
   common-py. common-warp's `write_capture` already had the `schema_version`
   kwarg → bumped its default to 1.1.0 + added `MAX_SUPPORTED_VERSION` + a
   `version > MAX` guard. The C++ `Manifest` default bumped 1.0.0 → 1.1.0 via a
   new `kMaxSupportedSchemaVersion` constant (its tests set the version
   explicitly, so the default bump is safe).

3. **The real validator is the testkit `CaptureManifest`.** `from_dict`
   schema-validates; extended with an optional `gradient_fields` field (default
   `None`) and a `to_dict` that OMITS `None` optionals. The testkit
   `write_capture` was switched from `asdict()` → `manifest.to_dict()` so a
   legacy 1.0.0 capture never serializes `"gradient_fields": null` (which would
   fail the array-typed schema property). This was a real regression caught by
   the common-py/common-warp suites and fixed.

4. **Legacy corpus = 26 pairs, of which 9 are Phase-1 descriptor placeholders.**
   (Pre-dispatch probe said 26; this measured the internal structure.) The 9
   placeholders (`boids-3d-ref`, `eulerian-smoke-ref`, `lattice-boltzmann-d3q19-ref`,
   `mandelbulb-explorer-ref`, `mpm-multimaterial-ref`, `physarum-ref`,
   `reaction-diffusion-3d-ref`, `sph-water-ref`, `strange-attractors-ref`) have
   text-stub `.h5` payloads ("PHASE-1-STAGE-2 PLACEHOLDER — not an HDF5 file")
   and `"checksum": "sha256:placeholder-…"` + a `_phase_1_stage_2_note` key, so
   they **did not validate against the schema at 1.0.0 either**. The HARD-gate
   round-trip test classifies them LOUDLY (sentinel checksum + non-HDF5 payload
   + identical-at-1.0.0/1.1.0 validation failure) — NOT silently excluded. The
   **17 real captures** round-trip fully. This is a documented SHIFT from the
   plan's "~25 loadable captures round-trip" assumption.

## §3 — Taichi `-W error` interaction (FACT, load-bearing for the entry gate)

`import common_py` triggers Taichi's `locale.getdefaultlocale` DeprecationWarning,
which the testkit's `filterwarnings = ["error"]` would escalate at collection.
The HARD-gate round-trip test therefore reads through the testkit `capture` layer
(the shared validator both backends delegate to) + the **common-warp** reader
(locale-clean); the **common-py** reader's legacy round-trip lives in common-py's
own suite (`test_legacy_reader_roundtrip.py`) under its Taichi-ignoring ini. The
common-cpp reader is skipped (no Python-callable binding) per plan § 7.2 step 2.
The per-package canonical run is plain `pytest` (the ini provides strict-warnings
+ the Taichi ignore), NOT CLI `-W error` (which overrides the ini).
