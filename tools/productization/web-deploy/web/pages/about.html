what it means when this project says “verified”

The posture

Bit-Physics is a portfolio of GPU physics and emergence simulations built around one discipline: no claim ships before it is measured, and no measurement is discarded after it ships. Every simulation runs from a committed, seeded initial state; its behaviour is captured, the capture is pinned, and every later build — native or browser — must re-earn agreement with that pinned evidence through an explicit gate. The records of those gates form an append-only ledger that ships with the code.

Tolerances are measured, then declared — never widened to make a failing gate pass. Audits close with four-state verdicts — CONFIRMED / SHIFTED / REFUTED / DEFERRED — and when reality disagrees with the plan, the audit records the SHIFT instead of rewriting the claim.
  • Deterministic, seeded runs — the browser boids flock steps from the same committed seed-42 initial state every load, and its gate requires two independent runs to be byte-identical. → boids-ic-seed42.bin (the committed IC) · verify.py (the run-twice gate)
  • Pinned canonical captures — reference runs are committed artifacts (HDF5 + manifest), not numbers in a wiki; gates compare against them field by field. → tests/fixtures/legacy-captures/ (e.g. boids-3d-ref.h5 / .json)
  • Tolerances under version control — every equivalence tolerance lives in a committed ledger with a CI check that refuses silent widening. → tolerance.toml · tolerance-budget.toml · tolerance-budget-check.yml
  • Four-state verdicts — the audit vocabulary is defined once, in the architecture document, and used everywhere. → docs/architecture.md (“Four-state verdicts”)
  • Append-only audit chain with SHA evidence — audits are never amended; commit SHAs are back-filled as new appends, so the evidence trail can be replayed against git history. → docs/_audits/ (phase 0 → 6) · phase-5 close

The discipline, in action

Three exhibits from the current polish lane — the rule is “measure before naming”, and the interesting part is what it rejects.

The flocking preset that measurement refuted REFUTED

A boids preset named “schooling” (alignment weight 3.0) was proposed for the live page. Measured before shipping, its global polarization came back 0.015 — local schools cancel, nothing globally “schools” — so the name was refuted by the measurement and the preset was rejected. The four presets that did ship each carry their measured order parameters.

→ Lane B P-4 audit § 7

The presets that honestly don’t exist SKIPPED

Growing Neural CA exposes only two live knobs without touching its trained kernel. Both were measured: synchronous fire-rate kills the pattern (0 alive cells — blank canvas), sparse fire-rate is indistinct from canonical. No measured-distinct watchable regime exists, so the sim shipped without presets rather than with decorative ones.

→ Lane B P-5 audit § 5.1

The critical magnet, anchored to theory CONFIRMED

The Ising temperature presets are named against the exact Onsager critical temperature Tc = 2/ln(1+√2), cited from the in-repo spec and golden table — not from memory. At the critical preset the measured energy per spin, −1.428, sits at the exact critical value −√2 ≈ −1.414, and magnetization collapses above Tc as theory demands.

→ Lane B P-5 audit § 5.3 · ising spec · golden table

Interactive without contamination

The live pages are playable — presets, cursor forces, orbit cameras — and none of it can leak into the evidence. The pattern is capture pinning: live interaction drives one parameter buffer, while the capture path re-runs from the committed seed with a second, canonical buffer whose call sites are disjoint (a one-grep proof recorded per audit). Every sim’s Study mode shows an honesty note stating exactly what is faithful, what is simplified, and what is measured live — including that camera framing is presentation-side and simulation state is unaffected.

  • The two-buffer pinning split, in code — stepCanonical() appears only inside the capture loop, stepLive() only in the animation loop. → boids-3d main.ts · proof transcripts in P-5 audit § 4
  • The honesty-note contract every sim fills in — faithful / simplified / measured, plus the gate verdict it shipped under. → common-web panel-shell.ts
  • Display-only changes are ratified, isolated, and proven byte-stable — the boids camera-fit landed as a standalone commit with pre/post frame hashes and an unchanged capture digest. → render.wgsl (header documents the proof) · phase-6 audit ledger

Don’t trust it — re-run it

Everything above is re-runnable from a clone. The browser gate needs a WebGPU-capable Chromium.

# build the seven web sims and re-apply each one's own gate
# in a real headless browser-WebGPU session (7/7 must pass):
python tools/productization/web-deploy/pipeline.py validate \
    --artifacts /tmp/out --json
  • The validate pipeline — vite build → headless browser drive → the sim’s established gate re-applied to the browser-emitted capture. No DOM-load substitutes. → pipeline.py · verify.py
  • The audit chain — start at the phase-5 close (7/7 browser-WebGPU green on CI) and walk the phase-6 lane audits forward; every push cites its validate artifacts. → docs/_audits/
  • Release binaries — native Stack-C capture binaries with SHA256SUMS, validated in the publishing run itself; verify the digests against the release body and the ledger. → release v0.5.0-phase-5

Who builds this

One developer, with AI agents doing the execution under operator-ratified dispatches: the operator scopes and ratifies each unit of work, agents build and measure it, and the audit ledger records what actually happened — including the rejections. The verification posture predates the pixels: the gates and the append-only ledger have been in place since phase 0.
