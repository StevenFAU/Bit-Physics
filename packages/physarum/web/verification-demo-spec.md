## 1. Purpose

Elevate the deployed Physarum demo from a *canvas + settings panel* into an *instrument* — and, per the § 2.2 survey, into the **first physarum demo anywhere** that (1) shows a live conserved-quantity readout and a re-runnable correctness check, (2) grounds each pattern in the real science it mirrors (Nakagaki maze-solving, Tero Tokyo-rail, Burchett cosmic-web) and, for the food-seeded scenarios, **measures the emergent network against a mathematically exact optimum**, and (3) renders the algorithm inline with the executing code. The creative-coding physarum canon is vast and beautiful but frames the sim as *generative art*; **not one surveyed demo does the verification leg at all** (§ 2.2, spot-checked and confirmed). That is this repo's thesis, and physarum is where it is most visibly uncontested — and, uniquely, where the sim's *reason for being famous* (it computes near-optimal transport networks) is itself a checkable claim.

Three features carry it. **Mass conservation:** the trail field holds an *exact* closed-form equilibrium `M = d·N·(1−α)/α = 5·500·0.9/0.1 = 22500`, gated at rel < 1e-3 (browser measured 22499.996, rel 1.7e-7; `docs/perf-ledger.md:90`) — a conserved quantity the visitor can watch converge and re-check live, *continuously, every frame* (§ 3.3). **Integer-atomics determinism:** two runs are byte-identical *because* the deposit is `u32` fixed-point (×65536), making `atomicAdd` order-independent where float atomics would be non-associative and non-deterministic — the gate itself records this (`tools/productization/web-deploy/verify.py:543`). No demo in the survey teaches why a parallel stochastic sim can be bit-reproducible; this one shows it (§ 3.3). **Network optimality, made honest:** in the science scenarios, the exact minimum spanning tree of the food points (computed client-side) is overlaid as the optimum baseline, so the visitor sees how close the emergent network comes to Tero's TL_MST ≈ 1.75 — the sim's headline scientific claim, shown rather than asserted (§ 3.1, § 3.3).

## 2. Why this sim (recommendation rationale)

- **FACT.** Gate is `new_canonical` — run-twice byte-identical + the mass-balance invariant, `physarum_mass_rel = 1e-3` (`tools/productization/web-deploy/verify.py:513-545`; threshold `T_PHYSARUM_MASS_REL` at `:66`). Fourth in the rollout; reuses the `new_canonical` kind (Lorenz) but on a 1M-scale-capable agent sim with a conserved quantity.
- **FACT.** Run-twice byte-identical, class `bit-exact-same-hw`, via **integer fixed-point `atomicAdd<u32>`** (`packages/physarum/src/physarum.wgsl:10-13`, `:75-76`; canonical manifest `captures/physarum-ref/network-canonical-seed42-step5000.json:19-21`; gate note `tools/productization/web-deploy/verify.py:543`). The deposit is the sim's **only cross-invocation reduction** — every other op (sense/rotate/move/diffuse) is per-invocation IEEE-deterministic — so integerizing this one atomic is *sufficient* for same-hardware bit-exactness (§ 3.2). The "run it twice → identical hash" proof succeeds even though the deposit is atomic — the physarum-unique story (§ 3.3).
- **FACT.** The mass equilibrium is an **exact closed-form invariant** derivable from the kernel: `apply` adds `d·N` per step (`packages/physarum/src/physarum.wgsl:84-85`), `diffuse` box-blurs (sum-preserving under periodic BC) then multiplies the field by `(1−α)` (`:96-103`); steady state `M = (M + dN)(1−α)` ⇒ `M = dN(1−α)/α = 22500`. It is **invariant in the morphology axes** (Δφ, L_sense, L_move: the value stays 22500 while the *pattern* changes completely) and **value-changing but formula-holding in the deposition axes** (d, N, α) — a two-sided demonstration (§ 3.2, § 3.3).
- **FACT (audit-trail verified).** Physarum was in the frontend shared-buffer set fixed by the Phase-5 harness-race resolution (`docs/_audits/phase-5/browser-divergence-resolution-landing-2026-06-09T13-24-25Z.md:92`); its **gated fields (trail_map + total_mass) were byte-identical to 5.1 before and after** the fix (0.0 diff; `…resolution-landing…:108` "physarum | identical (passing) | byte-identical; gate-field == 5.1 (0.0 diff) | new_canonical PASS (mass 22499.9962)"), while its non-gated agent positions were latently contaminated and corrected (`:70`, `:217`). The gate never regressed. Honesty angle: the conserved quantity held throughout.
- **FACT.** Self-contained: one 3-pass compute kernel (`packages/physarum/src/physarum.wgsl`, 104 lines: `agents`/`apply`/`diffuse`) + one render pass (`packages/physarum/web/src/render.wgsl`, 33 lines); web app 431 lines (`packages/physarum/web/src/main.ts`). Already has Play/Study, four sensing presets, cursor-deposit interaction, mass diagnostics, honesty note, verdict — this work *completes* a strong base.
- **FACT (cross-surface).** numpy-reference oracle (`docs/perf-ledger.md:22`) + webgpu-headless browser (`docs/perf-ledger.md:90`). (No pypi/native rows for physarum at HEAD — confirm against `docs/perf-ledger.md` at build time before claiming a cross-surface strip.)
- **FACT (positioning, survey-confirmed).** The § 2.2 survey found the "verification-visible + science-grounded + template-gallery" intersection is **uncontested** — no browser physarum demo does any of the three verification criteria (spot-checked: Sage Jenson 36 Points is an art NFT series; Lague is a coding-adventure; Bewelge is a Three.js sandbox — none exposes a conserved quantity, a determinism check, or a re-runnable correctness test).

### 2.2 Prior art & positioning (web survey 2026-07-03, fact-checked against primary sources)

Surveyed the physarum landscape — the canonical model, the landmark science, the cosmic-web application, and the creative-coding/GPU demo lineage. **Every number below was verified against the primary paper text in the v0.2 pass; deviations from the v0.1 draft are noted.**

- **Canonical model.** Jones 2010, "Characteristics of Pattern Formation and Evolution in Approximations of Physarum Transport Networks," *Artificial Life* 16(2):127–153 ([DOI](https://doi.org/10.1162/artl.2010.16.2.16202)). Agents sense a trail field at three forward sensors (sensor angle SA, sensor offset SO), rotate toward the strongest by rotation angle RA, move, deposit `d`; the field diffuses (3×3 mean) and decays (α). Canonical set: Δφ=45°, L_s=9, L_m=1, d=5, α=0.1 (`docs/sim-specs/agent-based/physarum/algebraic.md:26-27`). **Morphology rule:** RA<SA → contraction/reticulation, RA>SA → branching/dendritic. **[v0.2 CITATION FIX]** this rule is in Jones 2010 itself and in **Jones, [arXiv:1511.05869](https://arxiv.org/abs/1511.05869)** ("Mechanisms Inducing Parallel Computation…") — **not** arXiv:1503.03261 (the v0.1 draft mis-cited that; it is Jones & Adamatzky on statistical estimation, unrelated). *(Note: this repo's kernel couples RA=SA=Δφ — see § 8 rejected-with-cause.)*
- **Landmark science (the template hooks).** Nakagaki 2000, "Maze-solving by an amoeboid organism," *Nature* 407:470 ([Nature](https://www.nature.com/articles/35035159)) — a one-page Brief Communication: the plasmodium fills the maze then retracts from dead-ends, leaving one thick tube on the **shortest path** between two oat-flake food sources. Tero 2010, "Rules for Biologically Inspired Adaptive Network Design," *Science* 327:439–442 ([Science](https://www.science.org/doi/10.1126/science.1177894), [primary PDF](https://markfricker.org/wp-content/uploads/2015/12/tero_et_al-2010-science-327-439.pdf)) — **36 food sources at Tokyo-area city positions**; all three performance measures normalized to the minimum spanning tree. **Verified figures (quotable):** transport efficiency **MD_MST = 0.85** for *both* the real rail network and Physarum; cost **TL_MST = 1.75 ± 0.30** for Physarum (rail ≈ 1.8). **Honesty note:** fault tolerance (FT) is the **one metric where the real rail network beat Physarum** — worth stating, since it is exactly the kind of "the biology didn't win everywhere" detail this repo surfaces rather than hides. Adamatzky — shortest path / spanning / Steiner trees ([PubMed 17603779](https://pubmed.ncbi.nlm.nih.gov/17603779/)); **caveat:** optimality is *approximate and contested* — do not claim guaranteed-optimal (see the reality-check, [arXiv:1712.03139](https://arxiv.org/abs/1712.03139), "When the path is never shortest").
- **Cosmic-web application (the science-validation exemplar).** Burchett, Elek et al. 2020, "Revealing the Dark Threads of the Cosmic Web," *ApJL* 891:L35 ([IOPscience](https://iopscience.iop.org/article/10.3847/2041-8213/ab700c), [UCSC](https://news.ucsc.edu/2020/03/cosmic-web/)) — a Monte Carlo Physarum Machine (MCPM, [arXiv:2204.01256](https://arxiv.org/abs/2204.01256); Polyphorm, [arXiv:2009.02441](https://arxiv.org/abs/2009.02441)) reconstructed dark-matter filaments from **37,000 SDSS galaxies** (figure verified), validated three ways (Bolshoi-Planck N-body fit, star-formation-density correlation, Hubble/COS quasar absorption-line spectra). The MCPM is **3D and probabilistic**. The rare case of a physarum sim checked against independent ground truth.
- **Creative-coding / GPU lineage.** Sage Jenson "36 Points" ([sagejenson.com/36points](https://www.sagejenson.com/36points/)); Sebastian Lague ([repo](https://github.com/SebLague/Slime-Simulation)); Softology parameter atlas + multi-species RGB ([blog](https://softologyblog.wordpress.com/2019/04/11/physarum-simulations/)); Fogleman ([repo](https://github.com/fogleman/physarum)); Amanda Ghassaei gpu-io ([demo](https://apps.amandaghassaei.com/gpu-io/examples/physarum/)); Bewelge Physarum-WebGL ([demo](https://bewelge.github.io/Physarum-WebGL/)); WebGPU: SuboptimalEng ([repo](https://github.com/SuboptimalEng/slime-sim-webgpu)), Jeffrey Yuen ([demo](https://jkhyuen.github.io/physarum)). Converged GPU pattern: agent buffer → sense/rotate/move/atomic-deposit → diffuse+decay ping-pong → colormap render (matches this repo's kernel). Yuen's shareable parameter strings are prior art for the § 3.1 shareable-URL idea — they reproduce *inputs* for exploration and assert no correctness (a distinction this demo makes explicit).
- **White space (positioning, argued from the above and spot-check-confirmed).** (a) **Verification/determinism/mass-conservation: absent** — every demo is art/sandbox; none shows a conserved-quantity readout or determinism check. (b) **Re-runnable correctness check: none.** (c) **Network-optimality *measured*: none** — the demos grow beautiful networks but never compare them to the MST/optimum the science is about. (d) **Science-grounding: rare and one-directional** — only research tools (Polyphorm) tie the algorithm to validated science; no browser demo lets you toggle between "toy" and "the actual Tokyo-rail / cosmic-web scenario." (e) **Inline equation-with-live-code: absent.** This demo takes all five.

### 3.3 Layer 3 — PROVE (verification bound to real data)

- **Flagship — live mass-conservation gate (physarum's cheap-and-exact advantage):** display `total_mass` converging to and holding at the `d·N·(1−α)/α` equilibrium line, and re-run the gate criterion live — `mass_rel = |M − M_eq| / M_eq` vs the 1e-3 threshold → PASS/FAIL — on the visitor's GPU (mirrors `_gate_physarum`, `tools/productization/web-deploy/verify.py:521-530`). Unlike rd2d/ising (which re-run their gate in a one-shot scratch pass because a field/ensemble compare is expensive), physarum's invariant is a single sum — **so this readout runs continuously, every live frame**, tracking convergence in real time. On the canonical regime `M_eq = 22500` and the live field reproduces the exact committed gate criterion; on a deposition preset `M_eq` moves and the readout tracks it (the two-sided demo, § 3.2).
- **Falsifiability probe ("make it fail")** — three Lane-B-safe demonstrations that the invariant is real, not decorative:
  - *Open system converges to a predictable higher line (upgraded in v0.2):* with a science-scenario (or cursor) food source injecting a known total `f` per step, the balance is not merely "broken" — it re-converges to the **predicted** equilibrium `M = (d·N + f)(1−α)/α`. Draw both the closed line (22500) and the predicted open line; show the field climbing to the open line, then removing food and watching it fall back. The invariant *generalizes and still predicts* — a stronger statement than "external food breaks it."
  - *Perturbed-target gate:* re-run the mass check against a deliberately wrong canonical mass and render `mass_rel ≫ 1e-3 → FAIL` in red — the gate shown failing on purpose, so PASS reads as a test result, not decoration. UI labeling must make the deliberate-wrongness unmissable (must not screenshot as a real failure).
  - *(scenario, honest optimum comparison)* the **MST-overlay** (§ 3.1) is itself a falsifiability surface: the exact shortest tree is drawn, so a visitor can see the physarum network is *not* the MST (it carries redundant loops for fault tolerance — precisely Tero's finding, where FT is the metric the biology *wins* on and cost is where it pays ~1.75×). The optimum is shown, not asserted; the gap is visible.
- **Run-twice proof + the integer-atomics honesty contrast (physarum-unique):** run the canonical 5000-step protocol twice into scratch buffers (never the live `Ta`/`Tb`/`posB`/`headB`), SHA-256 each `trail_map` via `crypto.subtle`, and show the two digests are **identical to each other**. Then EXPLAIN *why*: the deposit is `u32` fixed-point ×65536, so `atomicAdd` is order-independent (`packages/physarum/src/physarum.wgsl:10-13`, `:75`), where float `atomicAdd` would be non-associative → non-deterministic (the gate records exactly this, `tools/productization/web-deploy/verify.py:543`).
  - **FACT — cross-hardware honesty (correction, new in v0.2).** The class is `bit-exact-same-hw`. The two live runs match *each other* on any single GPU (integer atomics remove the only ordering nondeterminism). They match the **committed sha** `6c0c239e…` (`captures/physarum-ref/network-canonical-seed42-step5000.json:25`) **only on the reference RADV hardware**; on other GPUs the non-atomic float passes (sense/diffuse) round differently, so the trail field — and its sha — differ **while the mass stays exactly conserved**. Display it this way: "your two runs are byte-identical (determinism ✓); if you are on our reference GPU they also match the committed hash; otherwise the field differs by float rounding while mass is bit-exact — *that is exactly why the gate is determinism + the mass invariant, not a field-hash match.*" This mirrors the ising lesson (browser digest ≠ NumPy sha, explained not hidden) and is the honest version of the v0.1 "show identical digests beside the committed sha" — which would have read as a false promise on non-RADV visitors.
  - **FACT (constraint):** `crypto.subtle` requires a secure context; the validate harness serves over localhost and Pages over https, so both qualify. Plain-language notice instead of a broken button if unavailable.
- **Verification card** bound to committed files (§ 4): gate `new_canonical`; mass threshold 1e-3; recorded browser mass 22499.996 / rel 1.7e-7 (`docs/perf-ledger.md:90`); run-twice byte-identical; determinism `bit-exact-same-hw`; provenance (seed 42, 256², 500 agents, 5000 steps, payload `sha256:6c0c239e…`). ### 3.4 Layer 4 — RENDER (presentation quality, physically bound)

Upgrade `packages/physarum/web/src/render.wgsl` (33 lines). **Principle (shared with the ising/rd2d specs):** every luminous element is bound to a physical quantity — no arbitrary bloom.

- **Bilinear reconstruction of the trail field.** The trail is a *continuous* concentration field (unlike ising's discrete lattice, where fat-pixel AA is the honest default), so bilinear interpolation of the four neighboring cells is the honest premium look — smooth organic membranes instead of the current nearest-neighbor blocks. Colormapped as **chemoattractant concentration** via the shared module (`common/common-web/src/colormap.ts` — `packColormap()`/`emitColormapWgsl()`; consume, never edit). Keep a **"raw grid" honesty toggle** back to nearest-cell texels at 256² ("what the buffer actually holds"). hiDPI backing store (CSS size × min(devicePixelRatio, 2)).
- **Gradient-lit relief (the "make it look like matter" move — new in v0.2).** Compute the trail-field gradient by finite difference in the fragment shader (reads the same storage buffer — data-derived, no kernel re-implementation) and apply cheap diffuse+specular emboss lighting: the vein network rises into glowing ridges, the low-trail voids recede. - **Flow / activity layer (the living pulse — bound to the deposit channel).** A render-owned snapshot of the `depB` deposit buffer copied via `copyBufferToBuffer` **after the `agents` pass and before `apply` clears it** (the one strict ordering constraint — `apply` zeroes `depB` at `packages/physarum/src/physarum.wgsl:86`). The snapshot is per-frame deposit = where agents are *actively moving right now*; the fragment shader adds it as a subtle luminous flow over the resting trail. Finite-difference-in-time, the rd2d activity-glow precedent applied to physarum. Frame-indexed cadence (poster/loop-deterministic). No compute pass added.
- **Inspection lens + optional agent overlay.** A pointer-following magnifier reading local trail values ("inspect the concentration"), and an optional overlay drawing the agents themselves as points (a live-only readback of `posB`, or a render pass over the position buffer) — the swarm made visible over its trail.
- **MST-overlay rendering.** The § 3.1 MST baseline drawn as a thin Canvas-2D (or second-pass) line set over the WebGPU canvas; food points as small markers. Presentation-only.
- **Poster + loop regeneration:** physarum is a motion-loop sim — regenerate both if the default look changes (`tools/productization/web-deploy/web/pages/make-posters.mjs`, `make-loops.mjs`).

## 8. Out of scope & rejected-with-cause

- **Portfolio-wide** extractor, methodology dashboard, data-driven landing page; the other demos; publishing (operator-dispatched; no write token here).
- **Full trail→graph network extraction + measured transport-efficiency — REJECTED for core, operator-strikeable stretch.** Skeletonizing the live trail into a graph to compute the physarum network's *own* TL/efficiency (vs the MST) is fragile (thresholding, thinning, junction detection) and risks a misleading number. The MST *overlay* (§ 3.1) delivers the honest, exact half — the optimum shown beside the emergent network — without claiming a precise ratio. A measured-efficiency estimate is recorded as an operator-strikeable follow-up, gated on a robust extraction (§ 9).
- **Separable RA ≠ SA morphology axis — REJECTED (kernel change).** The committed kernel couples rotation angle to sensor angle (`nh = hl/hr` are the heading rotated by ±`delta_phi`; `packages/physarum/src/physarum.wgsl:55-67`), so the literature's RA-vs-SA branching↔contraction rule (§ 2.2) is not separable without a kernel edit → Lane A. The morphology templates use the available axes (Δφ, L_sense, L_move, d, α) and this coupling is stated honestly in EXPLAIN.
- **Maze with obstacle walls — REJECTED (kernel change).** The kernel has no obstacle/collision term; true Nakagaki maze-solving needs agents to respect walls → Lane A. A food-only "connect two points" scenario is offered instead, labeled as such (not a walled maze).
- **Multi-species (RGB) — REJECTED (kernel change).** Single trail field, single agent species (`packages/physarum/src/physarum.wgsl`); Softology/Fogleman-style multi-species needs per-channel trails + inter-species coupling → Lane A.
- **True 3D cosmic web / MCPM — REJECTED (different sim).** The kernel is 2D; the Burchett/Elek MCPM is 3D probabilistic (§ 2.2). The "cosmic web" template is a 2D food-seeded homage, explicitly labeled — never presented as the actual reconstruction.
- **Image-seeded / color-steering agents — REJECTED (kernel change).** Needs per-agent color state + color-match steering → Lane A.
