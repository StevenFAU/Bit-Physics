## 1. Purpose

Elevate the deployed 2D-Ising demo from a *canvas + settings panel* into an *instrument* that makes the backend's testing and determinism discipline **visible and interactive** — the third application of the template, and the one where the verification act is most literally reproducible in the browser.

Ising completes the three-gate-kind trilogy the landing page advertises. Its gate is `observable`: energy-per-spin z-scored against a NumPy reference ensemble, threshold 3.0 (`tools/productization/web-deploy/verify.py:321`, `:355`). Because the gate criterion *is a statistic*, the demo can **re-run the gate on the visitor's own GPU** — measure energy-per-spin live, compute the z-score against the committed reference distribution, and display PASS/FAIL — and can build its own browser-side ensemble beside the NumPy one (§ 3.3, the flagship). Ising also uniquely carries **exact closed-form anchors** (Onsager's Tc, Yang's spontaneous-magnetization curve), so the demo can plot the *measured* magnetization against a *1952 analytic result* live — verification and pedagogy in one figure (§ 3.2 → § 3.3 fusion). The § 2.2 survey found **no demo anywhere that does this** — it is the single highest pedagogy-per-line feature in the space, and it is exactly this repo's thesis.

## 2. Why this sim (recommendation rationale)

- **FACT.** The gate is `observable` — energy-per-spin z-score < 3.0 vs a 6-seed NumPy ensemble (`tools/productization/web-deploy/verify.py:321-372`; threshold `T_ISING_Z = 3.0` at `:67`, established string at `:57`). Distinct from Lorenz (`new_canonical`) and rd2d (`capture_roundtrip`) → completes the trilogy.
- **FACT.** Ising is **run-twice byte-identical**, class `bit-exact-same-hw` (canonical manifest `captures/ising-classical-ref/metropolis-128sq-T2.27-seed42-step10000.json:16-19`; spec-ref determinism `docs/sim-specs/lattice-spin/ising-classical/spec-ref.md:140-149`, `:167`; the PCG-per-cell checkerboard kernel uses no atomics/subgroup ops, `packages/ising-classical/src/metropolis.wgsl:12-15`). The "run it twice → identical hash" proof succeeds.
- **FACT (audit-trail verified).** Ising was in the frontend shared-buffer set fixed by the Phase-5 harness-race resolution (`docs/_audits/phase-5/browser-divergence-resolution-landing-2026-06-09T13-24-25Z.md:92`), but its **gated observable was byte-identical to 5.1 before and after** the fix — no gated regression (`…resolution-landing…:107` "ising-classical | identical (passing) | byte-identical (== 5.1) | observable PASS"; `:70`). So ising's honesty angle is not a divergence post-mortem (that's rd2d's) but the **live reproducibility of a statistical gate** (§ 3.3).
- **FACT.** Closed-form anchors, exact and teachable: Onsager 1944 `Tc = 2/ln(1+√2) ≈ 2.2692`, Yang 1952 `m(T) = (1 − sinh⁻⁴(2β))^(1/8)`, Kramers-Wannier 1941 duality `sinh(2β_c) = 1` (`docs/sim-specs/lattice-spin/ising-classical/spec-ref.md:72-80`), with `m(T)` matched by the sim to `magnetization_rel = 5e-2` (`…spec-ref.md:180`). Enables a measured-vs-analytic figure no other sim has — and per § 2.2, no other *demo* has either.
- **FACT.** Self-contained: one compute pass (`packages/ising-classical/src/metropolis.wgsl`, 81 lines) + one render pass (`packages/ising-classical/web/src/render.wgsl`, 27 lines); web app 425 lines (`packages/ising-classical/web/src/main.ts`). Already has Play/Study, three temperature presets, cursor spin-flip, E/M diagnostics, honesty note, verdict — this work *completes* a strong base.
- **FACT (cross-surface).** Ships web + a pypi wheel that re-emits the canonical **bit-exact 0.0/0.0** in a fresh venv (`docs/perf-ledger.md:65`) + the numpy-reference oracle (`docs/perf-ledger.md:46`); browser baseline `docs/perf-ledger.md:87`. No native binary (`docs/sim-specs/lattice-spin/ising-classical/spec-ref.md:219` `binary: false`).

### 2.2 Prior art & positioning (web survey, 2026-07-03)

Surveyed the academic/educational browser-Ising landscape (Bierbaum [ising.js](https://mattbierbaum.github.io/ising.js/), Schroeder [Weber State](https://physics.weber.edu/schroeder/software/demos/isingmodel.html) + `thermal/isingHTML5.html`, [Veritasium criticality sim](https://www.veritasium.com/simulation4), [NetLogo Ising](https://ccl.northwestern.edu/netlogo/models/Ising), Demidov's [WebGL2 shader Ising](https://www.ibiblio.org/e-notes/Perc/ising.htm) (512²–1024²), [Complexity Explorables](https://www.complexity-explorables.org/explorables/i-sing-well-tempered/), [Beardsley's parallel-worker T-sweep](https://www.tbeardsley.com/projects/montecarlo/ising2d), Physics-of-Risk, Wolfram Demonstrations) and the GPU/industry lineage ([NVIDIA ising-gpu](https://github.com/NVIDIA/ising-gpu), Preis et al. 2009 checkerboard scheme, Google TPU-Ising, D-Wave/Toshiba annealer marketing). Findings that shape this spec:

- **The field splits three ways and nobody holds the intersection:** fast-but-unmeasured (WebGL shader sims with zero readback → zero observables), measured-but-slow (canvas + plots at ≤512²), polished-but-narrow (Veritasium: one observable). A GPU lattice **with** live quantitative observables **with** verification is the open best-in-class slot — and it is precisely this repo's existing architecture (WebGPU compute + `readSpins` readback + a statistical gate).
- **The GPU-Ising research lineage validates against Onsager but never renders its verification** — NVIDIA's repo and the Preis/Block papers assert correctness via magnetization tables in text. A demo that *shows* the checkerboard kernel running while *showing* its gate clear is unclaimed territory.
- **Table stakes** (present in the good demos, so ours must have them): smooth live T control spanning the transition, live E/M readouts with running stats, Tc explicitly marked (Veritasium's T/Tc-normalized readout is best practice), h field control. § 3.1 covers all four.
- **First-anywhere features this spec now claims deliberately** (absent in every demo surveyed): live measured-|M| overlaid on **Yang's exact curve** (§ 3.3); a statistical gate **re-run in the visitor's browser** with reference-ensemble histogram (§ 3.3); a **falsifiability probe** that makes the gate fail honestly on demand (§ 3.3 — no demo anywhere shows what failure looks like, which is why none of them read as *tests*); a flip-**activity layer** that doubles as a susceptibility visualization (§ 3.4); a raw-bit **inspection lens** with checkerboard-parity mode (§ 3.4).
- **Verification-presentation patterns adopted from industry tooling** (drift-monitoring and benchmark-gating UIs — Evidently-style distribution cards, CodSpeed-style per-check threshold rows, asv-style run history): reference distribution as a muted filled strip, acceptance band shaded, the live sample as a bright marker animating in, compact `z = 1.46 · |z| < 3.0 · PASS` gate rows, provenance chips. § 3.3 specifies the card this way.
- **Deliberately rejected** after survey: algorithm toggles (Wolff/Swendsen-Wang — kernel change, hard boundary § 6; critical slowing down is instead *named* in EXPLAIN and *visible* in the activity layer), grid-size selector (N=128 is hardcoded with buffers allocated once at `packages/ising-classical/web/src/main.ts:85-88`; reallocation churn for no verification value), bloom/glitter post-processing (expert audiences read unmotivated glow as compensation — every luminous element here is bound to a physical quantity), S(k)/correlation-length instrument (genuine white space but exceeds this demo's tone budget; recorded as a candidate follow-up in § 8).

## 3. Scope

Four additive layers. Nothing here mutates `packages/ising-classical/src/metropolis.wgsl` (the compute kernel), the capture pinning, the gate, `tolerance*.toml`, or the seed-42 IC asset. The render shader `packages/ising-classical/web/src/render.wgsl` **is** in scope: presentation, not a compute kernel; the gate reads GPU buffer readbacks via `readSpins` → `exposeCapture` (`tools/productization/web-deploy/verify.py:332`), never canvas pixels — so render-side changes cannot perturb the gate (§ 6).

### 3.1 Layer 1 — INTERACT (raise to prototype tactility)

- **Live temperature slider** as the primary control; the 3 regimes (`REGIMES`, `packages/ising-classical/web/src/main.ts:162-178`) become jump-to bookmarks. Only `liveParamBuffer` is rewritten per change (`packages/ising-classical/web/src/main.ts:98`, sweep `:184-206`) — the RAF already runs `STEPS_PER_FRAME = 4` live sweeps (`:28`), so no readback in the hot path. Sweeping T through Tc drives the order→disorder transition live.
  - **Range & annotation:** T ∈ [0.5, 5.0], tick at **Tc = 2.2692** (Onsager) and at the three preset temperatures (1.5, 2.27, 3.5). Label Tc as the exact `2/ln(1+√2)`, and show a **dual readout `T = 2.27 · T/Tc = 1.00`** (the normalized form is the § 2.2 best practice — it makes "how close to critical am I" legible at a glance).
- **Guided experiments strip** — three one-tap protocol buttons with a single caption line each, applied through `liveParamBuffer` only (the Complexity-Explorables "try this" pattern; pedagogy as presets, not prose):
  1. **Slow cool** — animated T ramp 3.5 → 1.5 over ~20 s; watch symmetry break as domains nucleate and compete.
  2. **Quench** — instant T drop 3.5 → 1.5; watch domain coarsening (caption names the `L(t) ~ t^1/2` growth law; the measured-L(t) instrument itself is operator-strikeable, § 9).
  3. **Critical sit** — T = Tc; watch scale-free fluctuations (pairs with the activity layer, § 3.4).
- **External-field h slider (optional, operator-strikeable — § 9).** `h` is a kernel uniform currently pinned to `PARAMS.h = 0` in the sweep write (`packages/ising-classical/web/src/main.ts:194`); routing the live `h` into `liveParamBuffer` only (never the canonical path) is Lane-B-safe and lets visitors force magnetization / watch hysteresis. Range h ∈ [−0.5, 0.5]. If kept, include the **M–H hysteresis loop trace** under a slow sinusoidal h(t) drive — the § 2.2 survey found no browser Ising hysteresis tracer anywhere, so this option is also a first. Flagged because it adds a physics axis beyond the canonical protocol.
- **Cursor spin-flip brush** already exists (paints a +1 disk, `injectCursorSpins`, `packages/ising-classical/web/src/main.ts:339`, `FLIP_RADIUS = 6` at `:317`); add a **brush-radius control** and a **paint −1 / paint +1 toggle** (domain seeding), through the same `queue.writeBuffer` path. Live loop only. (Guided-experiment tie-in: "paint a droplet below Tc and watch surface tension shrink it.")
- **Order-parameter readout in Play:** surface the existing Study observables (E/N, M, |M|, T/Tc; `packages/ising-classical/web/src/main.ts:284-296`) as an always-on lightweight panel, not Study-only. Add the **headline throughput counter** — Metropolis attempts/s (`128² × STEPS_PER_FRAME × fps`, ≈ 3.9 M/s at 60 fps; display-only arithmetic). Industry leads with a number; ours is honest and live.
- **Criticality panel (optional, operator-strikeable — § 9).** χ = N(⟨M²⟩−⟨M⟩²)/T and C = N(⟨E²⟩−⟨E⟩²)/T² time-averaged over a rolling readback window, **plus a cluster-size histogram (log-log)** from a client-side flood fill on the same low-rate readback (16,384 cells — trivial in JS; the Veritasium power-law-at-Tc figure, § 2.2). These *peak/go-scale-free at Tc* — the finite-size signatures of the transition. Flagged: heavier (needs a low-rate readback series) and adds statistical-mechanics depth that may exceed the demo's tone budget.

### 3.2 Layer 2 — EXPLAIN (equation → code legibility)

- A collapsible "Equations" panel group (via `addGroup()`, `common/common-web/src/panel-shell.ts`) rendering the Ising Hamiltonian, the Metropolis acceptance rule, and the checkerboard update, sourced from `docs/sim-specs/lattice-spin/ising-classical/spec-ref.md:47-65`.
- **The code IS the equation:** alongside each term, quote the actual committed WGSL line —
  - Hamiltonian `H = −J Σ⟨ij⟩ sᵢsⱼ − h Σ sᵢ` (`…spec-ref.md:49`) → neighbour sum `packages/ising-classical/src/metropolis.wgsl:70-72`
  - flip cost `ΔE = 2sᵢ(J·Σ + h)` → `packages/ising-classical/src/metropolis.wgsl:75`
  - Metropolis accept `min(1, exp(−ΔE/T))` → `packages/ising-classical/src/metropolis.wgsl:76-79`
  - checkerboard parity (detailed balance) → `packages/ising-classical/src/metropolis.wgsl:64`
  - PCG per-cell RNG (why the field can't match NumPy's PCG64 — motivates the observable gate) → `packages/ising-classical/src/metropolis.wgsl:47-58`

  Snippet text and line anchors are **extracted at build time** by `gen-verification.mjs` (§ 4) via exact-substring match against the committed shader — the build HARD-FAILs if a pattern stops matching (self-healing links). GitHub blob URLs with `#L<n>` anchors.
- **Closed-form anchors panel:** render Onsager Tc, Yang's `m(T)`, and Kramers-Wannier duality (`…spec-ref.md:72-80`) — the exact results the sim is checked against. This panel is the on-ramp to the § 3.3 measured-vs-analytic figure.
- **Two expert-credibility notes** (one line each, tooltip-weight): (a) *finite size* — at L=128 the apparent transition is shifted/rounded, so the § 3.3 overlay is framed as "consistent with the finite-L system," not "measures Tc"; (b) *critical slowing down* — single-flip Metropolis decorrelates slowly near Tc (why the activity layer seethes there, and why cluster algorithms exist; we deliberately keep the canonical kernel). Naming these is itself a trust signal to expert visitors (§ 2.2).
- No math-rendering dependency: hand-rolled markup on `common/common-web/src/theme.css` classes.

### 3.3 Layer 3 — PROVE (verification bound to real data) — flagship: live statistical gate

- **Flagship — live gate re-run (the observable, reproduced in-browser):** the gate computes `z = |E_browser − μ_ref| / spread` against a 6-seed NumPy reference ensemble (`tools/productization/web-deploy/verify.py:344-356`). Ship the committed reference stats `μ_ref`, `spread` (via § 4) and, at equilibrium, measure `E_browser` on the visitor's GPU and display **`z = X.XX` vs the 3.0 threshold → PASS/FAIL**, with the sample plotted on the reference distribution. If a visitor's GPU produced an outlier it would say so, verbatim — a demo that can fail honestly in front of you. This is the `observable` gate, re-run live.
  - **Presentation (drift-card pattern, § 2.2):** reference ensemble as a muted filled strip/histogram with the ±3·spread acceptance band shaded; the visitor's sample as a bright marker that animates in when the measurement completes; a compact gate row per check (`E/N  z = 1.46  |z| < 3.0  ✓` style); a PASS/FAIL verdict chip; **provenance chips** (seed 42, descriptor `metropolis-128sq-T2.27-seed42-step10000`, payload sha prefix, reference `ising_numpy` 6-seed). A small **session history strip** appends a row per re-run — repeated green runs communicate discipline better than one.
  - **Browser ensemble mode:** run K seeds live in-browser, histogram their `E/N`, and overlay the NumPy reference `μ_ref ± spread` — showing the two ensembles agree (self-averaging). The statistical-verification thesis made visible.
- **Falsifiability probe ("make it fail") — NEW in v0.2:** a clearly-labeled control that re-runs the same live-gate protocol with a **deliberately wrong parameter** (equilibrate at T = 1.5 instead of 2.27, into scratch buffers) and renders the honest result: `z ≫ 3 → FAIL`, red, with the sample marker landing far outside the acceptance band. One line of caption: *"the gate has teeth — wrong physics fails it."* No surveyed demo ever shows failure (§ 2.2), which is exactly why none of them read as tests. Governance: pure live-path parameter change + scratch buffers; kernel, canonical path, and gate code untouched (§ 6). UI labeling must make the deliberate-wrongness unmissable (it must not screenshot as a real failure).
- **Measured-vs-analytic magnetization (EXPLAIN→PROVE fusion, the ising signature):** as the temperature slider sweeps, plot the live-measured `|M|` against **Yang 1952's exact curve** `m(T) = (1 − sinh⁻⁴(2/T))^(1/8)` (`docs/sim-specs/lattice-spin/ising-classical/spec-ref.md:78-80`), with Onsager's Tc marked. The measured points landing on a 1952 analytic result (within `magnetization_rel = 5e-2`, `…spec-ref.md:180`) is a verification event the visitor watches happen. Frame per the § 3.2 finite-size note (the L=128 tail above Tc is expected and labeled, not hidden). Survey verdict: **no demo anywhere overlays the exact curve on live data** — this figure alone distinguishes the instrument. (Optional "auto-sweep T and trace M(T)/E(T)" mode — operator-strikeable, § 9.)
- **Live "Run it twice" proof:** reload the canonical seed-42 IC, sweep the canonical 10000-step protocol twice into scratch buffers (never the live `spinBuffer` state), SHA-256 each final spin lattice via `crypto.subtle`, display the two identical digests + byte count (128²×4 = 65,536 bytes). Ising is run-twice byte-identical, so this succeeds.
  - **Honesty contrast line (NEW in v0.2):** display the canonical NumPy payload sha (`cf844e5d…`) beside the two browser digests with the explicit note that the browser digest **does not and should not equal it** — the WGSL PCG per-cell RNG differs from NumPy's PCG64, so the microstates differ while the physics statistics agree; *that is precisely why this sim's gate is `observable` rather than a field compare* (`packages/ising-classical/web/src/main.ts:8-12` already records this rationale as a comment; the demo now says it out loud). Turns a potential "why don't the hashes match?" gotcha into the sim's clearest teaching moment.
  - **FACT (constraint):** `crypto.subtle` requires a secure context; the validate harness serves over localhost and Pages over https, so both qualify. Show a plain-language notice instead of a broken button if unavailable.
- **Verification card** bound to committed files (§ 4): gate `observable`, threshold z < 3.0; recorded browser z = 1.46 and ensemble mean −1.418 (`docs/perf-ledger.md:87`); run-twice byte-identical; determinism `bit-exact-same-hw`; provenance (seed 42, 128², T 2.27, 10000 sweeps, payload `sha256:cf844e5d0485a228f2bf9d7acc738097f6c09f7b5534d76d6dd096feb7ca9cbc`). Replaces the hardcoded verdict/honesty literals (`packages/ising-classical/web/src/main.ts:372-384`) and the manifest placeholders (§ 2.1).
- **Cross-surface strip (optional):** "same protocol, three surfaces" — numpy-reference oracle, the **bit-exact pypi wheel roundtrip** (`docs/perf-ledger.md:65`), and the browser (`docs/perf-ledger.md:87`) — evidence of the § 2.6 discipline.

### 3.4 Layer 4 — RENDER (presentation quality)

Principle (from the § 2.2 survey, stated as a constraint): **every luminous element is bound to a physical quantity.** No bloom, no particles, no unmotivated glow — expert audiences read decoration as compensation.

- **Antialiased-nearest lattice sampling as the default look.** The current fragment shader draws flat two-tone spins with plain sampling (`packages/ising-classical/web/src/render.wgsl`, 27 lines). At 128² blown up to ~800 px (≈6.25×, non-integer), plain nearest shimmers and bilinear lies about the data. Adopt the fat-pixel AA idiom — crisp texel interiors, texel *edges* antialiased over exactly one screen pixel via `fwidth` + `smoothstep` on the fractional UV (~5 lines of WGSL). Crisp texels are the honest premium look: the visitor sees the actual state. Keep a **"raw nearest" honesty toggle** (bilinear demoted to a labeled option, no longer a contender for default), plus hiDPI canvas sizing.
- **Spin palette + domain-boundary emphasis:** upgrade the two-tone palette (near-dark + accent on the dark theme) via the **landed** shared colormap module (`common/common-web/src/colormap.ts` — `packColormap()`/`emitColormapWgsl()`; consume, never edit from here). Extract domain boundaries in the fragment shader (4-neighbour spin compare) and draw them as a thin fwidth-AA line — makes coarsening fronts and the fractal interfaces at Tc legible.
- **Flip-activity layer (upgraded from v0.1's afterglow; the render feature with physics content):** render-owned prev-frame snapshot via `copyBufferToBuffer` (the Lorenz-trails precedent, `packages/strange-attractors/web/verification-demo-spec.md` § 3.4) + a small render-side ping-pong "activity" texture: cells that flipped since the last frame light up and decay (×≈0.95/frame). No compute-kernel change — comparison and decay live entirely in render passes. Physics payoff: the activity field is a live acceptance-rate map — **dark and frozen below Tc, seething everywhere at Tc, uniform noise above** — i.e. the susceptibility story told by the renderer, and the visual companion to the § 3.2 critical-slowing-down note. Toggleable; modest intensity.
- **Inspection lens:** a circular magnifier following the pointer, re-sampling the spin buffer at 4–8× with sharp texels inside — "inspect the raw bits," thematically exact for a verification instrument. Second lens mode tints cells by **checkerboard parity** (the red/black update sets, `packages/ising-classical/src/metropolis.wgsl:64`), making the update structure — a known subtle-bug zone in GPU Ising implementations (§ 2.2) — directly visible. Fragment-shader-only.
- **Poster regeneration:** ising is a static-poster sim (no motion loop). Regenerate its poster if the default look changes (`tools/productization/web-deploy/web/pages/make-posters.mjs`).

## 4. Data spine (per-sim, minimal)

- **New:** `packages/ising-classical/web/gen-verification.mjs` — a build-time script emitting a **committed generated module** (per the Lorenz v2.1 decision — not a runtime-fetched `public/` file), wired via `prebuild`/`predev` in `packages/ising-classical/web/package.json` (currently has neither hook — verified), with an **idempotence check** (re-running produces a byte-identical module or the build fails). It reads the sim's real values + WGSL snippet anchors. Scoped to this sim only. Template: `packages/strange-attractors/web/gen-verification.mjs` (fail-hard on missing file / unmatched anchor / unparsed threshold).
- **Reference ensemble stats for the flagship (`μ_ref`, `spread`).** The gate builds these at runtime from the NumPy reference (`tools/productization/web-deploy/verify.py:344-354`; spread = max(SEM, full σ) per `:354` — the browser is treated as an independent 7th sample, and the demo's live z must use the **same** spread convention). Preferred source: `gen-verification.mjs` invokes the same reference ensemble (via the repo's `uv` Python env) to emit `μ_ref`/`spread`, so the demo's live z uses the exact reference the gate uses — self-updating, not retyped. Fallback (if build-time Python is undesirable): record the committed web-deploy values (`docs/perf-ledger.md:87`) with a provenance comment. **Operator note (§ 9):** neither option adds a gated golden; both are read/record only.
